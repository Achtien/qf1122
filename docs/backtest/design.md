# 回测行为、架构与存储契约

本文记录已实现的回测行为、数据契约和文件职责。现有数据库和字段口径见
[查询示例](../database/querying.md)；行情主库为 `data/daily_data/daily_data.db`。

## 一次回测的边界

- 一次运行指定策略及参数、起止日期（两端包含）、交易所范围、初始资金、价格口径、指标定义和数据快照。日期格式沿用 `YYYYMMDD`。
- 引擎按区间内交易日升序运行。三个策略回调确定为**盘前 `before_open`、开盘 `on_open`、收盘后 `after_close`**，随后执行日结。收盘后就是当日交易已经结束、完整日线可用的阶段。
- 策略可调度的股票集合定义为当天 `tradable_stock.is_tradable=1` 的全部股票（下文记为 `U_d`）；可批量读取 `U_d` 每只股票的历史行情及自己的订单、成交和持仓历史。股票池不按当前仍上市的名单筛选。`is_tradable=0` 或 NULL 的记录不进入 `U_d`，其原因计入数据质量报告。
- 这是一个**理想化价格回测**：只在开盘价或收盘价成交；不计手续费、税费、滑点、市场冲击、可用成交量和涨跌停限制。`U_d` 中股票只要目标价有效，就允许按任意正整数手数全额成交。现金不能为负，卖出不能超过当日可卖持仓；沿用 A 股 T+1 约束。手对应的股数作为市场参数固定并写入运行配置。
- 公司行为仅通过选定的价格序列体现，例如复权价格。引擎不产生分红现金、送转股份、配股认购或换股流水。

## 每日阶段与订单时序

先验证区间、行情覆盖与 `market_calendar`；交易日取所选交易所开市日期的并集，当日只处理实际开市的市场。未知日历不能当休市静默跳过。区间首尾落在休市日时，从区间内第一个开市日开始，到最后一个开市日结束。策略可为回看计算读取起点前的历史，但不在区间外成交。

| 顺序 | 阶段 | 策略可读取 | 本阶段可产生的成交 |
| --- | --- | --- | --- |
| 1 | 盘前 `before_open` | 当日 `U_d`、这些股票截至前一交易日的历史行情、此前交易历史和账户状态 | 可提交当日 `OPEN` 或 `CLOSE` 订单；尚未读取当日开盘价或收盘价 |
| 2 | 开盘 `on_open` | 当日 `U_d`、历史行情、当日开盘价、盘前订单的成交结果及最新账户状态 | 先执行盘前 `OPEN` 订单，再执行开盘回调；回调新提交的 `OPEN` 订单也按**同一个当日开盘价**成交，`CLOSE` 订单留到收盘撮合 |
| 3 | 收盘撮合 | 不调用策略 | 将此前提交的当日 `CLOSE` 订单按当日收盘价成交 |
| 4 | 收盘后 `after_close` | 当日 `U_d`、截至当日的完整行情、当天全部成交及账户状态 | 不回填当日成交；新订单最早指定下一交易日的 `OPEN` 或 `CLOSE` |
| 5 | 日结 | 当日全部结果 | 按收盘价估值，计算指标，一次事务写入订单、成交、账户、指标和完成检查点 |

开盘回调**看见开盘价后仍可按该价成交**，是用户指定的理想化假设，不能解释为真实交易能力。收盘价只能由收盘前已提交的订单使用；收盘后回调看到当日 `close` 后，不能再让订单以当天 `close` 成交。订单必须带目标日期与 `OPEN`/`CLOSE` 标签；不能指定其他价格或回填过去阶段。首版订单只支持全额成交或明确拒绝，不模拟部分成交。目标价缺失或非有效数值、股票不在目标日 `U_d`、现金不足或当日可卖持仓不足时，订单拒绝并保存原因。

三个回调使用同一类 `Context`：日期、阶段、当日 `U_d`、受阶段限制的行情读取接口、下单接口、只读账户快照、只读交易历史和策略私有状态。历史查询只返回当前阶段之前已经发生的事件。盘前不能通过历史接口读取当日价；开盘只额外开放当日 `open`；收盘后开放当日完整日线。策略可以批量请求 `U_d` 的历史，底层按日期与股票代码分批读取，避免把全市场全区间行情一次载入内存。

`ctx.status(code, date=None)` 及 `ctx.statuses(date=None)` 向策略提供当日池和持仓的状态，支持无行情的停牌与退市日期，日期截止当前日。`tags` 与 `tags_unknown` 以元组返回，ST、*ST 及未知类别供策略明确筛选。`bars()` 和 `history()` 也附带对应历史标签。当前有效标签在盘前公开，沿用当日池的事后可见性假设。

### 当日 `tradable` 名单的含义

现有 `tradable_stock.is_tradable=1` 是利用**当日完整 OHLC 和成交量**得出的事后交易证据，见 [查询示例](../database/querying.md) 第 1.7 节。本设计按用户要求在盘前就把 `U_d` 提供给策略；因此回测含有**当日资格的事后信息**，可能高估选股效果。该假设写入运行配置和报告，报告不得把结果标为无未来信息的盘前策略。`U_d` 证明当天有交易证据，但不证明某一笔订单能以开盘价或收盘价成交；本引擎的无限流动性规则单独承担这个理想化假设。历史代码与 `security_id` 的映射尚未完整，遇到同一证券多代码或未知身份时需按固定规则去重/排除并在报告中列出。

## 价格和公司行为口径

每次运行固定一种 `price_basis`，策略读取、成交、持仓估值和指标计算使用**同一口径**的开盘价、收盘价，不在同一账户中混用原始价与复权价。允许的模式为：

| 模式 | 价格用途 | 结果解释 |
| --- | --- | --- |
| `raw` | 直接使用现有未复权 `daily.open/close` | 适合核对原始报价；遇到分红、送转等，价格变化不能单独代表真实持有收益 |
| `adjusted` | 使用固定规则生成的复权 `open/close`，完整历史采用同一锚点和数据版本 | 账户中的“手”和现金是复权价格模型的合成单位；净值反映所选价格序列，不代表真实股数及公司行为现金流 |

现有库**尚无复权因子**，`adjusted` 模式启用前需补齐因子或可信的复权价格序列，并记录来源、公式、锚点和版本。不能仅凭 `pre_close` 或 `pct_chg` 推出完整复权价格。若复权锚点包含回测终点后的资料，策略用绝对价格阈值时也可能引入未来信息；同一运行内不得随查询终点改变历史价格。公司行为不改变持仓数量，也不额外入账。若研究目标是实际现金收益和真实股份数量，此价格模型不足以给出该结果。

| `src/backtest/execution.py` | `OPEN`/`CLOSE` 全额撮合、现金/持仓校验和拒单原因；成交价严格取目标开收盘价 |
| `src/backtest/portfolio.py` | 现金与持仓批次、T+1 可卖数量、成本、收盘估值和账本对账 |

| `src/backtest/strategy.py` | 三个回调和受控 `Context` 接口 |

验收重点：固定 `U_d`、三阶段数据权限和价格口径；再接快照与交易日循环；随后实现开收盘撮合、账户与**每日指标**；最后实现 HTML/PDF 和续跑。首条验收链为：同一快照与配置重复运行得到相同订单、成交及逐日指标；所有成交价只取配置口径的当日 `open` 或 `close`；收盘后新订单不会回填当日；日结失败不留下半日记录；HTML/PDF 曲线与表格能逐项追溯到结果库。

## 一个回测对应一个结果库

每次运行只生成一个**数据文件** `strategy/<策略名>/results/<run_id>.db`，保存本次运行的配置、每日账户、持仓、订单成交、策略自定义数据、逐日指标输入和结果。回测完成后生成同名 `.html` 交互报告和 `.pdf`。`run_id` 与数据文件一一对应；库内仍保存 `run_id` 供导出核对。股票全市场历史数据保留在独立的只读行情快照中，结果库只保存实际用于该账户估值的逐股收盘价与参考序列输入。完整复现须同时保留所引用的行情快照；记录主库路径不能替代快照版本。

回测结果库采用单写入者。当天的账户和所有指标在**同一日结事务**中提交，不能出现账户已更新而指标仍是前一天的状态。结果库可采用 SQLite 回滚日志模式，使关闭后的持久数据只有 `.db` 文件；事务运行中可能短暂出现日志文件，异常退出时先完成 SQLite 恢复再归档，不能直接复制正在写入的 `.db`。策略中断后可查看最后一个完整日的账户和指标。

## 每日基本数据

每个日结日期必须保存两项基本状态：

1. `cash`：剩余现金，不含已购股票价值。
2. `positions`：每只已持股票的代码 `ts_code` 与实际拥有的**股数**。下单时的“手数”按运行配置中的每手股数换算，不能把“手”直接当“股”。

账户、续跑及核对所用表由 `src/backtest/schema.sql` 定义。

| 表 | 主键 | 保存内容 |
| --- | --- | --- |
| `run_info` | 单行 `run_id` | 策略/版本/参数、起止日、初始现金、每手股数、市场、价格及复权口径、行情快照 ID、报告情境、运行与报告状态、创建与完成时间 |
| `daily_account` | `trade_date` | 日终 `cash`、持仓市值、账户总资本、估值状态、策略状态检查点和完成标记；空仓日也有一行 |
| `daily_positions` | `(trade_date, ts_code)` | 代码、可选 `security_id`、日终股数、可卖股数、当日估值收盘价、价格实际日期、市值、JSON 标签 `tags` / `tags_unknown` 及 `status_reason`；只保存正股数持仓 |
| `position_lots` | `lot_id` | 买入批次、买入日期、剩余股数、可卖日期，用于既定 T+1 规则和恢复 |
| `orders` / `fills` | 各自 ID | 目标交易日、`OPEN`/`CLOSE`、方向、手数、状态、实际成交股数、价格、金额与拒单理由 |
| `cash_ledger` | `entry_id` | 初始资金及买卖产生的现金变动；本模型无手续费和公司行为现金流 |
| `events` | `event_id` | 异常、缺价、身份冲突、拒单及阶段顺序的审计信息 |

当日收盘估值采用与本次运行的信号和成交一致的 `price_basis`：

`positions_value_d = Σ(shares_{i,d} × close_{i,d})`；`equity_d = cash_d + positions_value_d`。

金额、股数、价格的单位与舍入规则要写在 `run_info`。`cash` 不得为负；持仓股数与成交、批次变化一致。每日提交前核对：逐股市值之和等于持仓市值、现金加持仓市值等于账户总资本、现金流水推导值等于日终现金。未成交订单不预扣现金；同一撮合阶段按稳定的订单序号依次处理，后续订单若余额不足则拒绝。

存储类型也固定：股数用整数；现金、成交金额、收盘价和市值用规范化十进制文本，并以十进制运算后按运行配置舍入，避免 SQLite `REAL` 的二进制浮点误差进入账本。指标比率和策略数值字段可另用有限的数值列供排序与聚合，但它们不作为现金账本的权威值。需要在数据库内汇总金额时，使用相同的十进制规则计算，不能直接把金额文本按字典序比较。

默认 `valuation="suspension"`。当 `tradable_stock.tags` 确认停牌且 `is_tradable=0`，或证券所属市场当日确认休市时，沿用同一证券身份、同一价格口径最近的有效收盘价。实际日期存入 `daily_positions.price_date`，账户状态为 `stale`。日内停牌且资格为 1 时使用当日价格。缺少日线、停牌未知及资格冲突时，缺乏有效报价的持仓和账户估值为 NULL，账户状态为 `missing`。新标签库报价需有同一身份的确认交易资格。`last_close` 显式沿用所有缺价日的历史有效收盘价，`strict` 使用当日有效收盘价。

`daily_positions.tags` 与 `tags_unknown` 保存当前日的确认标签和未知类别，`status_reason` 保存资格原因，例如 `FULL_DAY_SUSPENDED`、`NO_DAILY_DATA`、`SUSPENSION_BAR_CONFLICT`、`DELISTED`。状态字段和价格字段在同一日结事务提交，缺价持仓也保存状态。

已确认退市标签或同一证券身份的 `stock_basic.delist_date` 到期时，持仓估值、市值和可卖股数归零。休市日生效的退市在下一回测日结体现。三种估值模式均执行退市归零。原持仓身份与复用代码的新实体分别判断，原股数及买入批次留存，现金计入总资本，记录一次 `delisting_writeoff`。零估值的 `price_date` 为日结日期。`settings.delisting` 记录规则，损失当日进入收益与回撤。总资产归零时，当日收益为 -100%，以后连续零资产日收益约定为 0。

`run_info.settings.market_status` 记录 `tag_version` 及 `legacy`，共享状态模块的代码摘要也纳入执行签名。新标签库必须通过标签版本和结构检查，`tags_dirty=1` 时暂停制作与使用新快照。无标签旧快照返回未知状态，支持显式 `last_close`。旧结果库可继续导出报告，新字段由新回测生成。

`adjusted` 口径下，账户是复权价格的合成价格账户。

## 策略自定义数据

策略可注册需要持久化的字段：唯一名称、作用范围、类型、单位、描述及版本。核心账户表不随策略改变列。推荐一组扩展表：

| 表 | 用途 |
| --- | --- |
| `data_definitions` | 声明自定义数据及指标的名称、范围（运行/每日/逐股）、类型、单位、版本、产生者和缺失语义 |
| `strategy_daily_data` | `(trade_date, key)`；存策略自行定义的每日收益、信号、阈值等 |
| `strategy_position_data` | `(trade_date, ts_code, key)`；存逐股评分、目标仓位等 |
| `strategy_run_data` | `(key)`；存本次策略的非逐日补充信息 |

数值型字段单独用可计算、可排序的数值列，文本、布尔和结构化数据按声明类型存储；大对象不直接写入每日行。策略键用 `strategy.*` 命名空间；`account.*` 和 `benchmark.*` 留给引擎。策略自定义的“收益率”不会覆盖引擎按总资本计算的账户收益率。策略若要恢复内部状态，使用日终检查点，不能依赖展示型自定义字段。变更字段含义或公式须提升版本。

## 指标情境及输入

**账户日终序列只有一份，指标可以按多种情境逐日计算。**策略可在运行配置中定义一个或多个 `scenario_id`，每个情境分别指定无风险收益率、参考收益率来源、年化约定及自定义指标参数。每日日结时，按当时已有的全部账户日终序列计算各情境截至当天的指标。回测后新增情境时，应从已存账户序列按日期顺序补算并写入该情境**每一天**的指标，无需重跑交易。

| 表 | 主键 | 保存内容 |
| --- | --- | --- |
| `metric_scenarios` | `scenario_id` | 情境名称、无风险收益率来源/单位、参考序列标识及来源、年化交易日数、公式版本、参数 JSON 与是否用于 PDF |
| `scenario_daily_inputs` | `(scenario_id, trade_date)` | 与账户交易日对齐的当期无风险收益率 `rf_return`、参考日收益率 `benchmark_return`、可选参考收盘值及其来源、质量状态 |
| `metric_definitions` | `(metric_name, version)` | 公式、单位、日结或截至当日累计的口径、所需输入、最小样本数、缺失与零分母规则，以及引擎或策略计算器标识 |
| `daily_metrics` | `(scenario_id, trade_date, metric_name)` | 当日收益、累计收益、参考累计收益、夏普、信息比率、最大回撤额、最长回撤时间等**截至该日**的值，含状态、样本数、原因和可审计的中间量（均值、标准差、峰谷/恢复日期等） |

无风险收益率可以是固定年率、分段年率或逐日序列。固定年率 `R_f` 按本情境配置的每年交易日数 `N` 转成日率 `(1+R_f)^(1/N)-1`；所有来源最终冻结为逐日 `rf_return`。参考收益率默认取**上证综指**，也可改用其他指数、外部净值或策略定义的日收益序列；最终冻结为与账户日期一一配对的 `benchmark_return`。股票指数收益率不充当无风险收益率。允许另设无参考情境，此时信息比率和超额收益率为 NULL，记录 `NO_BENCHMARK`；默认无风险收益率为明确写入配置的零年率。

基准第一日收益需要回测首日前的基准值，或者数据源已明确给出的首日日收益。日期缺失、重复或非有限值应使该情境的相关指标不可计算，并列出缺失日；不能默默前填或填零。新增情境时记录数据来源与版本，以保证同一个 `scenario_id` 的结果可复算。账户收益与基准收益都采用同一组交易日、同一种简单收益率定义。

本项目的上证综指基准从行情库同一张 `daily` 表中按 `ts_code='000001.SH'` 读取，
每日一行；股票报价/持仓候选查询须排除这一代码。它不属于 `tradable_stock`，
不能通过股票池的内连接取得基准。行情与股票可能分批发布，指标计算前须独立核对
指数日期覆盖。默认用相邻上证交易日的指数收盘点位计算 `b_t=close_t/close_prev−1`，
首日需区间开始前的上一指数交易日收盘点位；这是指数**价格收益率**。将实际使用的
收盘点位、基准收益与口径冻结到 `scenario_daily_inputs`。
读取示例见 [查询示例 第 1.12 节](../database/querying.md#112-同表读取上证综指与对齐基准)。

## 每日计算的指标公式

设初始现金 `E_0=C_0>0`，第 `t` 个回测交易日日终总资本为 `E_t`，账户日收益 `r_t=E_t/E_{t-1}-1`；`b_t`、`f_t` 为本情境冻结的同日参考和无风险日收益。假设运行中没有额外出入金。**每个交易日**用从首日至当天的前缀序列 `1…t` 计算下表所有指标并写入 `daily_metrics`；回测结束时最后一天的记录就是全区间结果，不再重新定义或另算一套公式。

| 指标 | 本设计采用的定义 | 单位/说明 |
| --- | --- | --- |
| 账户总资本 | `E_t = cash_t + Σ(shares_{i,t} × close_{i,t})` | 账户价格口径下的金额 |
| 截至当日总收益率 | `E_t/E_0-1` | 小数收益率；PDF 展示时乘 100% |
| 截至当日夏普比率 | `sqrt(N) × mean(r_1-f_1,…,r_t-f_t) / sample_std(r_1,…,r_t)` | 年化约定下的比率；分母是账户日收益波动率 |
| 截至当日信息比率 | `sqrt(N) × mean(r_1-b_1,…,r_t-b_t) / sample_std(r_1-b_1,…,r_t-b_t)` | 年化主动收益 / 跟踪误差 |
| 截至当日参考收益率 | `∏_{j=1…t}(1+b_j)-1` | 与账户同一起点及日期；PDF 图中的参考曲线 |
| 截至当日超额收益率 | `账户累计收益率_t − 参考累计收益率_t` | 两条累计收益率之差，PDF 展示为百分点 |
| 当日回撤额 | `H_t−E_t`，其中 `H_t=max(E_0,E_1,…,E_t)` | 与总资本同单位；初始资金也是首个峰值 |
| 截至当日最大回撤额 | `max_{j≤t}(H_j−E_j)` | 记录对应峰值日和谷值日；可附最大回撤率 |
| 截至当日最长回撤时间 | 从首日至当天，账户总资本连续低于此前峰值的最长**交易日数** | 达到或超过旧峰值后当前计数归零；尚未恢复的区间也参与比较并标记 |

这里的夏普比率以无风险收益为参照、账户波动为分母；信息比率以基准收益为参照、主动收益波动为分母，两者不能共用一个“参照”参数。[CFA Institute 对两者的定义](https://rpc.cfainstitute.org/-/media/documents/code/gips/sharpe-ratio-and-the-information-ratio.pdf)支持这一拆分。`sqrt(N)` 是明确记录的年化**约定**；收益存在自相关时，该换算未必能代表实际年度分布，故结果库保留未年化日频均值、标准差和样本数。[CFA Institute 对年化限制的研究](https://rpc.cfainstitute.org/research/financial-analysts-journal/2002/the-statistics-of-sharpe-ratios)说明该限制。

收益率为小数而非百分数：`0.02` 表示 `2%`。标准差采用样本标准差（分母 `n−1`）。截至当天的有效收益日少于 2、相应标准差为零、必要净值或情境输入缺失时，该日对应指标为 NULL 并保存具体原因，不写零或无穷大；此后满足条件的日期正常产生值。最长回撤以低于峰值的连续**回测交易日**计数，峰值日与恢复日不计入；同时保存起点、谷值、恢复日或“尚未恢复”状态。若需要按自然日计算，应增加另一个有独立名称的指标。

策略可再注册指标，声明依赖字段、情境参数、单位、公式版本和缺失处理；每个自定义指标都应能在日结时基于截至当天的数据计算。样本不足时按定义写 NULL 和原因，不能等待回测末日才首次入库。自定义指标失败不覆盖基础账户数据；错误与原因存入指标状态。情境输入、指标定义和逐日结果同在此运行的 `.db` 中。

## 交互 HTML 与 PDF 结果

全部交易日完成后，生成 `strategy/<策略名>/results/<run_id>.html` 与同名 PDF。报告由 `report_scenario` 选择情境，默认参考为上证综指 `000001.SH`。HTML 内嵌曲线数据和脚本，浏览器可离线打开。悬停或触摸图表可显示日期和两条曲线的累计收益率，支持左右方向键及 Home/End，停牌沿用价的日期有估值标记。报告情境可设置为其他参考及无风险参数组合。

报告只包含图表、指标名称与数值、必要的标题/图例/单位和运行元数据，**不写结论、解释或文字分析**。默认内容如下：

| 区域 | 内容与数据来源 |
| --- | --- |
| 标题信息 | 策略名、回测起止日期、初始资金、参考序列名称、价格口径、`run_id` |
| 对比图 | 横轴为回测交易日，纵轴为**累计收益率（%）**；红色策略线和蓝色参考线分别读取选定情境 `daily_metrics` 中每日账户累计收益率和参考累计收益率；两者以回测开始前的 0% 为同一起点 |
| 指标表 | 显示运行配置选定的全部基础和策略自定义指标；数值取**最后一个已完成交易日** `daily_metrics` 中该情境的值，带单位和适当小数位 |

参考曲线须覆盖报告的每个回测交易日；缺日时不画断裂后仍声称完整对比，报告生成状态标为失败并指出缺失日期。某项指标因样本不足或零分母而为 NULL 时，表中显示“不可计算”，不补零。绘图和制表只读取已提交的 `.db`，不重新运行策略或重新计算另一套指标。HTML/PDF 先写临时文件，成功后替换目标文件，并将最近成功导出的报告路径、情境、生成时间和状态写入 `run_info`。两种格式同时导出后 `report_file` 指向 HTML；失败时保留完整 `.db`，可以单独重试报告生成。

## 写入与恢复顺序

1. 建库时写入 `run_info`、自定义数据与指标定义、预设情境及其逐日参考/无风险输入；默认参考为 `daily` 表的上证综指。校验首日前参考基准值、区间覆盖、价格口径与输入日期对齐。提前存入的未来参考数据只能由指标计算器按当前日读取，策略接口不得访问未来行。
2. 每个交易日按阶段处理订单，收盘后记录现金与持仓，按收盘价估值，并计算**截至该日**的全部已配置指标。订单、成交、流水、持仓、账户、策略自定义数据和当日指标在同一事务提交；已预存的情境输入只读取当前日期及之前的行。提交成功才视为当日完成。
3. 末日提交后，以该日日终 `daily_metrics` 作为全区间指标值，核对报告所需序列完整，再生成 HTML 和 PDF。指标不在此时首次计算。若报告失败，将 `report_status` 标记为 `failed`，日结记录保留；可只重试报告。
4. 中断续跑时，校验行情快照、策略、参考序列和价格版本；从最后一个已提交日的账户、持仓批次、策略检查点和累计指标状态恢复。未完成日整日回滚。

所有主键、外键和唯一约束应在 `src/backtest/schema.sql` 中落实。读入 SQLite `REAL` 行情后统一转换并按运行口径舍入。结果库保持单写入者，策略只能通过受控接口写入自定义数据和指标。
