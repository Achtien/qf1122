# 回测检验设计草案

两项检验回答不同的问题。第一项给定原策略已经买过的股票和实际持有区间，观察真实的涨跌顺序在随机排列中排在哪里。第二项保留完整策略，观察从十个不同时点空仓启动后，收益和夏普是否集中在少数区间。两项结果并列展示，各自给出可由数据支持的结论。

## 共用输入与指标

以一次已完成的回测结果库和对应的冻结行情快照为输入。分析只读原库，检查 `run_info.status`、快照 SHA-256、配置和交易日覆盖。交易日取配置内各交易所开市日的并集，按日期升序，与 `daily_account` 逐日核对。指标情境默认取原配置的 `report_scenario`，首版可选原配置中的其他情境。

| 指标 | 两项检验统一采用的口径 |
| --- | --- |
| 区间收益率 | 区间末日收盘总资本 / 区间初始资金 − 1。末日仍有持仓时按原估值规则计入，包含空仓日。下文的“收益率”均指这个累计值。 |
| 年化夏普比率 | 设日收益为 r，情境日无风险利率为 f，年化期数为 P。取 √P × mean(r − f) / sd(r)，分母是策略日收益的样本标准差。首日以上述初始资金为基数，f 按真实日期对齐。 |
| 结果之间的 E、σ | 对每个指标分别取有效结果的算术平均数和样本标准差（分母 m − 1）。m 为该指标的有效次数或段数。只剩一个有效值时可报均值，标准差留空。 |

复用 `backtest.metrics.Accumulator.update` 和 `Moments`。账户缺价、日无风险利率缺失、夏普样本不足或日收益零波动时，沿用引擎的逐指标缺值原因。零收益是有效数值；缺失夏普不能填零，也不应连带删除同一行有效的收益率。原始数值保存为小数，仅展示时把收益率换算成百分数，其跨样本标准差展示为百分点。[回测开发指南](../backtest/guide.md)

## 一、固定持仓，置换持有期内的涨跌幅

**固定什么。** 以实际成交为准，固定证券身份、进出日期、开盘或收盘时点、每次成交股数，以及同一时点的成交先后。原交易由跌停触发或因停牌延迟时，也取最终成交时点。置换中跳过策略回调，包括选股和卖出信号判断。这样测到的是给定交易安排后，价格路径顺序对组合结果的影响。选股贡献、止损规则在另一条价格路径上会何时触发，均超出这项检验的解释范围。

### 从成交重建可置换序列

1. 用 `fills.order_id` 连接 `orders` 取 `security_id`，按交易日、OPEN/CLOSE、成交 ID 重建股数。每只证券从股数由零变正到重新归零为一次连续持仓，期末未平仓则截止原回测末日收盘。中途加减仓保留各次交易；清仓后又买回时另起区间。逐日与 `daily_positions` 的股数和身份核对。
2. 从同一快照、同一 `price_basis` 的报价构造收益因子。一个完整持有日的因子为当日收盘估值价 / 上一交易日收盘估值价。可交易且有开盘报价时，同时记下开盘价 / 上日收盘估值价。两个比值作为一条日记录一起移动，使中途加减仓可在模拟的开盘价或收盘价成交。
3. 两端仅计入实际承担的涨跌。开盘买入当天固定“开盘至收盘”，开盘清仓当天固定“前收至开盘”，收盘买入从下一时段开始承担涨跌。收盘卖出当天若从前收一直持有，可作为完整日参与置换。以每次建仓的真实成交价为起点。例如周一开盘买、周五开盘清仓，固定周一日内和周五隔夜的因子，只在周二至周四间打乱三条完整日记录。
4. 在每只证券的每段连续持仓内，对普通完整日做均匀、无放回排列。不同证券、不同持仓段独立抽签。同一证券同一天的全部股数共用一个模拟价格。停牌沿用价、所属市场休市、退市归零、无可用开盘报价的日期固定在原位；沿用价取模拟路径上次有效收盘，复牌或恢复有效报价日的跨日涨跌也固定。退市后持续按零计值。真实持仓出现无法估值的日期时，报告日期、证券与原因，停止这项路径检验。空仓日期保留在组合日历上。

### 一轮模拟与对照

从初始资金和空仓开始，按置换后的因子逐日递推价格。对完整日，用模拟前收分别乘以该条记录的开盘因子和收盘因子；部分持有日使用上文对应的边界因子。按原成交股数在模拟价格上增减现金和持仓，闭市时以现金加各持仓市值计算总资本。成交、现金和估值按引擎的 Decimal 口径，不对中间模拟价格强制取整。现有引擎交易成本为零。原库的现金流水用于核对真实路径，随机路径的现金必须重新计算。

先以**原顺序**回放一次。逐日核对成交金额、收盘现金、股数、总资本，末日再核对指定情境的 `daily_metrics.sharpe` 与 `total_return`（浮点指标允许数值误差）。任何不一致先报告首个分歧的日期和字段，停止抽样。这次回放提供真实观测值，不计入 n 次随机排列。

配置项为重复次数 n 和随机种子 seed，建议初版默认 n = 1,000、seed = 0，n 至少为 2。每轮从原序列独立抽取一次排列，允许轮与轮之间重复，包括碰巧抽到原顺序。用稳定的证券及区间排序，按 seed 和轮次派生随机流，并记录生成器及版本。报价与成交时间线只读入一次，每轮生成一条组合净值序列，计算指标后即可释放。

固定历史股数有时会导致模拟现金不足，例如另一只股票在同日卖出所得低于真实值。该轮记录第一笔不可执行成交及原因，结束该轮，不借款、不缩量补单，也不补抽。汇总保留申请次数、可执行次数和各指标有效次数；出现不可执行轮次时，仅描述可执行子集，完整随机分布的越界结论标为不可判定。

### 如何读结果

每个指标单列真实值 x、有效次数、E、σ、E + 2σ、E + 3σ，以及 x 是否**严格大于**这两条上界。两者可同时为真。可同时列出有效模拟值中“大于等于 x”的个数，便于判断一个越界结果在实际抽样中有多少近邻。比较采用未格式化数值，在记录的浮点容差内视作相等。有效值不足两个、真实值缺失或 σ 在容差内为零时，给出原因，越界判断留空。

**为什么可能看不到差异。** 单股固定股数、区间内无加减仓时，期末价等于期初价乘以所有收益因子，调换乘法顺序不改变期末价。举例说，100 元先涨 10% 再跌 10%，与先跌 10% 再涨 10%，都以 99 元结束。若始终全仓持有这一只股票且日无风险利率固定，日收益只是换序，夏普也相同。报告应列出可置换日数、可置换持仓段数及各指标是否退化；加大 n 无法给恒定指标带来辨别力。

这里的上界是条件置换分布的描述阈值。它假定普通日的涨跌顺序可以互换，逐股独立置换还会改变同时持有股票之间的同期相关性。偏斜、离散或退化的分布没有固定的“2σ/3σ 显著性”解释。真实组合越界仅说明其路径在这套随机规则下靠近上尾。

## 二、按交易日等分，独立重跑十次

设原区间共有 N 个交易日，令 q、a 为 N 除以 10 的商和余数。按时间顺序，前 a 段各取 q + 1 日，其余各取 q 日，每段两端均包含。所有交易日恰好使用一次，长度最多相差一天。例如 253 个交易日拆为前 3 段各 26 日、后 7 段各 25 日。N 小于 10 时无法形成十个非空区间，返回原因；只有一个交易日的段仍计算收益率，夏普按样本不足处理。

| 环节 | 约定 |
| --- | --- |
| 启动 | 每段重新调用策略工厂 `build()`，使用同一冻结快照、策略代码、参数和辅助输入。由原 `Config` 仅替换 `start`、`end`。每段均使用原初始资金，从空仓、空委托、空 `ctx.state` 开始。 |
| 运行 | 调用 `backtest.engine.run` 生成独立子回测，按阶段执行完整的选股、进出场、T+1 和估值规则。按策略原有接口读取段首以前已知的行情，例如首日选股所用的前一交易日收盘；不带入此前生成的账户、信号或策略记录。需要运行积累状态的策略会经历真实的冷启动。 |
| 边界 | 最后一日照常处理开收盘和日结，持仓按收盘估值结算，段后委托遵循引擎的区间边界。下一段重新启动，不强制平仓，也不拼接十段净值。 |
| 取数 | 从各子库读取段末同一情境的 `sharpe` 和 `total_return`，同时列出实际交易日数、成交笔数、缺值原因和子库路径。全程空仓、净值恒定的段记录收益率 0，夏普为空。 |

开始前用原完整配置核对策略、引擎与辅助输入摘要；改变起止日期后，子回测自然会有自己的签名。项目中的 `limit_up_lowest` 按原运行访问过的日期准备部分输入，独立启动可能访问额外的市值批次。如果缺数，保留失败段和具体日期；若需补齐，先冻结一份覆盖所需日期的新输入，用同一版本重跑全期基线和分段，避免混用数据版本。

对十行结果按指标等权计算 E、σ，并列明有效段数和失败段。收益率均值描述一次典型长度区间的平均表现，夏普均值描述分段夏普的平均水平；全期累计收益和夏普另列为背景。十段均值不用于重构全期指标。若均值由个别高收益段抬高，具体的区间起止和数值应能从明细直接定位。十段均来自原历史样本，这项检验能揭示时段依赖；此前若用同一段历史调过参数，它仍属于样本内诊断。

## 拟议模块、调用与产物

| `src/analyse/` 模块 | 职责与接口草案 |
| --- | --- |
| `baseline.py` | `load_baseline(result_db, snapshot, scenario)` 校验来源，读取配置、交易日、情境输入及真实指标。 |
| `permutation.py` | `run_permutation(baseline, n, seed)` 构建连续持仓、做原顺序对账，返回真实值、逐轮结果和可置换规模。 |
| `segments.py` | `run_segments(baseline, strategy_path, output_dir)` 计算十段边界，加载全新策略实例，调度子回测并提取末日指标。 |
| `summary.py` | 按指标汇总有效数、均值和标准差；仅为置换检验计算上界和越界判断。 |
| `__main__.py` | 拟提供 `python -m analyse permute` 和 `python -m analyse segments` 两个入口，均接收原结果库、快照、情境和输出目录；前者另接 n、seed，后者另接策略文件。实现时将 `analyse` 加入项目已有的包发现配置。 |

每次分析写入独立目录。两种入口均生成 `manifest.json`（来源 run_id、签名、快照和辅助输入摘要、情境、分析版本、参数和比较容差）、`details.csv`（一轮或一段一行，含状态、指标值及各自缺值原因）、`summary.csv`（一个指标一行）。分段入口保留子库；置换入口保存轮次和种子，便于按需复算单条路径。失败行与有效行使用相同编号规则，部分完成时在汇总中明确标识。

## 实现验收

- **路径还原。** 用含开盘买、收盘卖、部分减仓、同日换股及期末持仓的用例逐日对账。开盘清仓日收盘后的行情不能影响收益，收盘建仓当日涨幅不能计入持仓收益。
- **置换边界。** 验证每段完整日因子在置换前后的多重集合相同，两次持有同一代码互不串段，沿用价与退市归零发生在原日。单股无加减仓的例子应得到相同终值；零波动、有缺值和模拟资金不足应分别显示对应原因。同种子复跑逐轮一致。
- **十段重跑。** 检查整除、有余数、少于十天三种日历；将一段按相同日期单独运行，对比逐日账户及末日指标。构造段界前持仓且有待卖信号的情形，验证下一段从空仓启动，仍可查到段首以前的已知行情。
- **汇总。** 用手算序列核对样本标准差、严格越界和有效分母。恰好等于上界时记为未超过；所有收益相同或没有可置换日时，明确显示指标退化。

## 运行与查看报告

项目环境中可运行以下命令。将三个输入路径替换为对应的已完成回测库、同次冻结行情和策略文件。

```sh
uv run --locked python -m analyse all "$BASELINE" --snapshot "$SNAPSHOT" \
  --strategy "$STRATEGY" --output-dir strategy/limit_up_lowest/results/analyse \
  --n 1000 --seed 0
```

单项入口为 `permute` 和 `segments`。前者无需策略文件，后者无需次数和种子。每次运行都会打印独立目录中的 `report.html` 路径。直接用浏览器打开，切换年化夏普与累计收益率，点击或用键盘聚焦柱形查看频数和区间信息。展开明细可查单次置换、单段结果及缺值原因。HTML 内嵌图表及数据，离线可用；一并复制同目录 CSV 和 JSON 可保留下载链接。若某段运行失败，报告保留其余结果和失败原因，命令返回非零退出码。

**复现测试策略。** `strategy/limit_up_lowest` 的原始辅助库按全期持仓路径采集。已具备十段覆盖的冻结副本时，直接使用副本中的 `strategy.py` 和匹配的全期基线。首次从原始库准备时，依次执行：

```sh
FROZEN=strategy/limit_up_lowest/results/analysis_inputs
uv run --locked python strategy/limit_up_lowest/prepare_analysis_inputs.py \
  --snapshot "$SNAPSHOT" --directory "$FROZEN"
uv run --locked python -m backtest run "$FROZEN/strategy.py" --snapshot "$SNAPSHOT"
```

准备工具在独立目录中复制已有输入并通过项目的 Tushare 客户端补齐各段实际访问的批次。第二条命令在该副本上生成全期基线。将其打印的数据库路径设为 `BASELINE`，将 `STRATEGY` 设为 `$FROZEN/strategy.py` 后运行上面的分析命令。对应原始快照名可从原结果库的 `run_info.snapshot_sha256` 查到。
